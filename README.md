# lets-listen

面向直播的桌面节目工具：本地播放音频/视频，在节目画面中显示封面、频谱、可滚动的歌曲简介和多人评分。支持内置 RTMP 推流，不需要 B 站直播弹幕 API。

## 已实现

- 多选或拖放导入音频/视频，自动生成带 TRACK 编号的播放队列
- 可将播放队列保存为 JSON 歌单，下次导入时恢复曲目顺序、当前选曲、手动封面、投稿人、作曲、曲风及简介等资料
- 读取常见音频标签和内嵌封面；艺人或作曲信息不会被当作投稿人，投稿人与曲风可在后台单独填写
- 有封面的音频会把封面柔化为节目画面背景，并从左侧向右侧渐隐；程序会提取封面的代表性色彩，作为主窗口、评分和后台的强调色；视频画面不叠加封面背景
- 独立直播后台可管理播放队列、导入媒体、播放进度、最高 125% 音量、信息卡透明度和本地评分，也能随时修改曲名、作曲、投稿人、曲风、封面与简介
- 16:9 节目输出画面和全屏节目模式，可由 OBS/直播姬窗口捕获
- 内置 FFmpeg 推流控制，可采集节目窗口与本软件播放音频；没有串流密钥时可先录制 10 秒 MP4 测试
- 原评论框改为自动滚动的歌曲简介区；不限制填写字数，不显示固定标题，只显示正文，并可调节背景透明度
- 视频播放时隐藏封面和频谱，保留 TRACK 编号、左侧曲目信息、评分数字和可滚动的简介区，并叠加半透明磨砂底
- 在主窗口或后台按“评分人＋评分”本地输入；同一评分人对同一首歌改分时覆盖旧分数，节目画面只显示平均分数字
- 评分、曲目信息变更和切歌事件以 JSONL 实时留档，并可导出带 BOM 的 CSV

## 本地运行

需要 Node.js 22 或更高版本。

```powershell
npm install
npm start
```

开发模式会自动打开开发者工具：

```powershell
npm run dev
```

运行检查和测试：

```powershell
npm run check
npm test
npm run test:e2e
```

`npm test` 运行单元测试；`npm run test:e2e` 在 Windows 桌面启动 Electron，检查后台编辑、简介滚动与显隐、本地多人评分与改分、即时导出、坏媒体报错、真实音视频播放和视频模式。它还会录制 10 秒 MP4，并把音频节目和真实视频节目分别推送到 `127.0.0.1` 的临时 RTMP 接收端；不会向外网推流。端到端测试需要可用的 FFmpeg 和图形桌面会话。

生成 Windows 发行目录：

```powershell
npm run dist
```

打包会使用 `npm install` 安装在本地的 Electron 发行文件，避免重复下载和解压 Electron。

可执行文件位于 `dist/win-unpacked/`。分发时将整个目录压缩为 ZIP，解压后运行其中的 `品味大战.exe`。

## 本地评分

1. 导入一首音乐或视频。
2. 点击播放队列中的曲目。
3. 如需补充资料，点击“编辑当前曲目信息”或“打开直播后台”，导入封面并填写作曲、投稿人、曲风和歌曲简介。
4. 在主窗口底部或直播后台的“本地评分”中填写评分人，然后输入 `#01 8.5`；也可以对当前曲目输入 `评分 8.5`。
5. 同一评分人再次评分时会覆盖此前的分数并重新计算平均分，但每次评分仍会写入存档。
6. 切换评分人即可录入多位参与者的评分。

命令也支持 `TRACK 01 8.5`。评论指令和普通文本不再被解析或存档。

## 保存与导入歌单

在主窗口左侧或直播后台点击“保存歌单”，选择一个 `.json` 文件；以后点击“导入歌单”即可恢复曲目顺序、当前选曲、曲名、作曲、投稿人、曲风、简介及其显隐状态、手动封面。导入会替换当前播放队列，软件会先确认；评分和播放进度不属于歌单，不会恢复。

歌单保存媒体文件和手动封面的相对路径与原始绝对路径，不复制音视频本体。把歌单和媒体一起移动时会优先使用相对路径；找不到的媒体会在导入确认时提示并跳过，找不到的手动封面会退回媒体内嵌封面（如有）。请在编辑曲目信息后先点击保存，再保存歌单。

## 直播后台与节目模式

点击左侧“打开直播后台”可打开独立控制窗口；进入节目模式时会自动打开。后台可导入或拖入音视频、选择曲目、播放/暂停、切歌、调整进度与音量，以及调节信息卡透明度、录入评分、内置推流和导出存档。节目模式下按 `Ctrl+Shift+D` 可以重新打开后台。若使用 OBS/直播姬，请用“窗口采集”选择主节目窗口；内置推流不需要 OBS。

后台还可以编辑队列中任意曲目的曲名、作曲、投稿人、曲风、封面与简介，勾选或取消“在节目画面展示简介”会立即生效。节目画面的简介区只显示填写的正文，没有固定标题；长文本会自动向下滚动，到底后停顿并从头继续。视频模式在视频上叠加 TRACK 编号、左侧曲目信息、右侧评分及简介，信息卡使用半透明磨砂底；曲目信息更新会记录到本场 JSONL 存档。切歌或更换封面时，主色会从封面重新提取；无封面时使用默认绿色，黑白封面使用浅灰色。

节目画面中的作曲信息可以从音频标签读取，也可以在后台或主窗口编辑；未填写作曲时回退显示音频标签中的艺人信息。作曲与投稿人分开保存，未填写投稿人或曲风时显示“待填写”。音量滑块最高为 125%，超过 100% 使用应用内增益，部分录音可能会失真。

切换后台正在编辑的曲目前，如果资料尚未保存，软件会先询问是否放弃更改。主窗口的编辑弹窗会绑定打开时的曲目；若后台同时修改了这首歌，旧弹窗会拒绝覆盖新内容，并提示关闭后重新打开。

## 内置推流（先用测试录制）

当前版本需要 Windows 上安装 FFmpeg 并加入 PATH，或在直播后台填写 `ffmpeg.exe` 的完整路径；它不会随仓库和 ZIP 自动附带。FFmpeg 负责把节目画面与本软件播放音频编码为 H.264/AAC。首次使用请在主窗口进入节目模式，在直播后台点击“录制 10 秒测试”，选择 MP4 保存位置，并播放歌曲。查看录像，确认画面、简介和声音都正常，再用于正式直播。

拿到 B 站直播中心提供的推流服务器地址和串流密钥后，分别填入后台的两个输入框，再点击“开始推流”。串流密钥只在当前运行内存中使用，不写入配置文件；停止或重启后需要重新填写。目前尚未用真实 B 站地址完成端到端推流验证。推流功能与直播弹幕 API 无关。

自动化测试只使用本地录制和本机环回 RTMP，不会连接真实直播间。正式 RTMP 推流仍需你在实际直播间验证；请在软件内输入串流密钥，不必把密钥放入仓库或测试脚本。


## OBS / 直播姬建议

1. 在软件右上角点击“进入节目模式”。
2. OBS 添加“窗口采集”，选择“品味大战”。
3. OBS 添加“应用程序音频采集”，选择本软件进程。
4. 画布建议使用 1920×1080。
5. 为避免下一曲自动播放时串场，画面会持续显示明确的 `TRACK` 编号。

## 存档位置

原始 JSONL 默认写入：

```text
用户文档\品味大战存档
```

每一行都是一个独立 JSON 事件，即使程序异常退出，已经写入的记录仍然有效。点击“导出存档”可把本场评分导出为 CSV。旧版存档中的评论记录不会被删除。
新存档使用 `trackId`，CSV 列名为 `track_id`；导出器也能读取旧版 `roundId` 记录。
